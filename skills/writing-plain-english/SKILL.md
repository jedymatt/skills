# Writing Plain English

The user isn't a native English speaker, and this text goes out under their name. Write the way a person talks. Code, identifiers, and quoted error messages stay as they are.

1. **Plain word over fancy word.** If a 10-year-old wouldn't say it, swap it:

   | Fancy | Plain |
   |---|---|
   | leverage, utilize | use |
   | ensure | make sure |
   | initiate, commence | start |
   | additional | more, extra |
   | distinct | separate, different |
   | significantly, meaningfully | a lot |
   | demonstrate | show |
   | prior to, subsequently | before, then |
   | approximately, numerous | about, many |
   | in order to, due to the fact that | to, because |
   | however, therefore, thus | but, so |

   The full list, with before-and-after examples, is in `reference/word-swaps.md`.
2. **One idea per sentence.** A semicolon, or a sentence over about 20 words, means split it.
3. **Cut filler:** just, really, actually, simply, quite, very, basically.
4. **Connect with** so, but, and, also. Not thus, hence, moreover, whilst.
5. **Say it directly:** "I fixed X", not "I went ahead and addressed the X issue".
6. **Keep technical terms.** Cache, deploy, dedup, refactor, race condition, rollback are normal. The rule is about everyday words.

Keep the meaning and the technical accuracy. Only the words get simpler. Contractions are fine. Short doesn't mean choppy.

Before sending, check the draft word by word against the table above, then for long sentences and filler. The first draft always has some.
